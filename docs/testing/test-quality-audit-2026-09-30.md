## 删掉的是什么

- 11 条只覆盖旧 `queryFirst` / `FillSession` 的用例：生产代码没有调用这些入口；当前身份门禁、统计、重复经历保护在运行管道有独立覆盖
- 4 条只调用旧 `matchElementToResumeField` 的用例：当前计划器仅使用同文件 `calculateTextMatchScore`，其测试保留；六个负样本迁到当前分析器与计划器
- 2 条旧 `replaySnapshot` API 用例：无生产调用；现代确定性重放的实际执行、禁止网页写入、篡改检测仍保留
- 2 条直接日期/Semi 选择正例：同样结构和值已在完整管道用例覆盖
- 1 条静态演示简历必须叫“张三”的检查
- 1 条只找提示词中的两句文案、不能证明模型安全行为的检查

本轮删除 21 条，加上上一轮已删除的 10 条，共 31 条。重写和重命名没有伪算成删除。

## 旧测试确实漏掉的错误

我们临时修改生产行为，分别运行基线与新测试，随后恢复原代码：

| 故意破坏 | 旧断言 | 新断言 |
|---|---|---|
| 删除短词边界判断，让 Google/Cat 等误命中 Go/C | 通过：只确认混有正确短词的文本包含正例 | 失败：分别检查纯负例和正例，大小词典均检查 |
| 删除弹窗“确定”动作 | 通过：fixture 在点候选时已经提交 | 失败：fixture 只在点确定后提交选择 |
| 把 Applicant Name 错映成手机号 | 通过：汇总 F1 仍超过95% | 失败：38个回归标签逐一要求正确 top key |

旧语义评测还把错误分类遗漏在召回率分母之外。现在删除这一误导性统计，保留明确的逐标签回归；开发语料不代表真实招聘网站总体准确率。

## 重点重写

- PDF 排版：从少数 indexOf 比较改为所有行/列内容和完整顺序；避免首个 token 缺失时 -1 仍满足小于关系
- 备份：真的导入旧数组；预览比较全部存储；覆盖前先放入旧投递；回滚检查规则、投递和激活简历
- 导入与资料衍生：检查是否自动保存、遗漏条目、显式 false/0、不改变输入、证书分数和荣誉时间边界
- TTL：模拟经过有效期边界，检查记录被实际清除
- 空简历：使用真正 EMPTY_RESUME，要求精确空列表，替代可能零次执行的循环断言
- 站点画像：不能只要生成任意 semanticKey 就算通过；每个结构要求正确字段 key 和 FILL
- Greenhouse：从复读配置对象改为扫描实际控件，检查 first/last/full name 三种不同结果
- 输入事件：检查完整事件顺序及自动填写标记过期，明确 tracker shim 不等于 React 集成测试
- 并发：原测试把队列写进 mock，不能验证真实 background。单元测试改为诚实的串行补丁/消息序列化；浏览器增加两个真实扩展页面同时发送四个字段补丁，检查全部保留。此新增浏览器场景以当前提交 CI 为准

大型重复经历案例保留在实际 Chromium 扩展流程中（40个字段）。单元综合正例缩为每类两条，仍验证所有内容、索引和重复执行幂等，另保留超过旧上限的专门检查，减少重复等待。

## 加强测试后暴露的实际问题

历史诊断中 `解析 candidate@example.com 和张三失败，实际值: 张三` 会隐藏邮箱及冒号后的值，但前面的张三仍留下。现在测试检查整条记录，同时要求错误上下文仍可读。

最小生产修复仅位于 `src/core/storage/fillHistoryStorage.ts`：先收集错误中明确标记的期望/目标/实际值，再隐藏同一值的其他重复出现。它不声称能识别无标签自由文本里的任意人名。

## 仍然没有被证明的部分

- 当前招聘厂商的所有真实控件与登录后流程；结构 fixture 和路由测试不能证明网站已适配
- 真正 React 受控应用的集成；现有 tracker 测试只保证 shim 契约
- 任意延迟的服务器校验、所有并发调度、闭合 Shadow DOM 和所有浏览器版本
- 远端大模型服务质量及其对恶意文档的行为；fetch mock 和提示文案不能证明这些
- My97 实际日历：现有用例明确只测消息/路由

已保留的安全、隐私、确认、取消、未知值、已有值保护和记录隔离用例仍有明确用途。后续增加测试应针对这些具体缺口或复现的失败，不继续堆注册数量与理想化成功断言。
