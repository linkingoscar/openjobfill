# 业务流程模块边界

本次重构保留现有浏览器扩展部署方式与填写内核，不引入新的状态库、服务端或依赖。

## 填写与悬浮入口

`FloatBall.vue → useFillSession → formFillerEngine / frameCoordinator`

- `useFillSession` 独占分析、预览、执行结果、错误、增量基线和页面变化提示的可写状态；组件只接收 computed 视图与 analyze/confirm/cancel 等操作。
- 生命周期为闲置 → 分析 → 预览 → 用户确认 → 执行。仅生成预览不会触发字段写入；重复点击不能并发执行同一预览。
- 取消、换简历、页面变化和组件卸载会使正在等待的操作失效。迟到的本地或跨域子页面分析结果被释放，不会恢复旧预览，也不会覆盖新会话。
- UI 的错误信息与填写历史通过明确的回调输出，不把抽屉选项卡或 toast 的可写引用传入会话。
- `DrawerFillTab`、`DrawerJDTab` 等只展示数据、发出事件；历史面板通过具名插槽组合，不持有运行状态。
- `useApplicationArchive` 管理投递草稿和经确认的持久化，不依赖填写会话；`mergePlatformProfile` 负责资料合并与经历去重，空基本信息不覆盖原值。

## 简历导入

`ResumeImportModal → useResumeImport → resumeImportService → 本地提取器 / 扩展后台 AI`

- 弹窗保留文件选择、拖放、图片预览和授权交互，不包含 PDF 转图、AI 消息组装或解析结果合并。
- 服务负责选择本地/AI 路径、检查授权、限制发送内容并调用已有合并逻辑。有本地结果时，AI 增强失败保留本地结果；纯图片失败则明确报错。
- 导入状态模块负责进度、错误和预览结果；重新选择、切换模式或卸载使旧请求失效。取消后未开始的 AI 调用不会再发起；已经发送到后台的请求目前不能保证立即中止或停止计费。
- `ResumeImportPreview` 展示结果并使用独立的 `assessResumeImport` 计算完整性提示。提示不是对简历真实性或解析准确率的评分。
- 导入服务不保存简历，仍由用户确认预览后交给原有管理页面保存。

## Schema 消费策略

字段名称、路径与可填写策略只在 `resumeFieldRegistry` 定义，消费方按用途投影：

| 消费方 | 空值 | 多段经历 | 问答库 |
| --- | --- | --- | --- |
| AI 字段匹配 | 不发送 | 实际有值字段 | 排除，交给专门匹配器 |
| 剪贴板 | 不展示 | 实际有值字段 | 保留既有用户主动选择能力 |
| 人工站点绑定 | 可选择，后续填写仍需有值 | 只展开当前存在的记录 | 排除，避免绕过作用域 |
| 诊断导出 | 无须填写值 | 仅结构信息 | 按脱敏策略处理 |

新增字段应登记到中心，不再往组件中增加平行字段表。新增流程应先确定状态所有者，不以组件体积或文件数量作为重构完成标准。
