## 🌟 核心特色

### 1. 🌲 规模自适应多模式匹配引擎（AC 自动机 / 朴素扫描双路径）

- 内置 Aho-Corasick 自动机（Trie + Fail 后缀图），检索复杂度 O(N + M)；
- 但小词典下 AC 的常数因子反而高于朴素扫描，因此引擎按词典规模**自动选择路径**：
  - 词典 < 300 词 → 走预编译小写关键词的朴素扫描，并跳过 Trie 构建；
  - 词典 ≥ 300 词 → 构建 AC 自动机，切换为线性扫描。
- 当前内置技术关键词词典约 100 词，实际走朴素路径。词典一旦扩充到阈值以上，调用方代码无需任何改动即自动切换。

### 2. 🧠 混合语义相似度匹配（编辑距离 + 2-Gram + 同义词词图）

- **Levenshtein 编辑距离**：动态规划，空间压缩至 O(min(N, M))；
- **字符级 2-Gram Jaccard**：集合重合度，对中文字序扰动更稳健；
- **人工维护的同义词词图**：覆盖政企、银行自建系统的生僻表单（如"生源地"、"户籍所在地"、"税前期望薪酬"、"紧急联系人"）；
- 融合权重：同义词直接命中为 1.0 / 包含匹配 0.95，否则取 `Jaccard × 0.6 + Levenshtein × 0.4`。

> 说明：此处**未使用 TF-IDF**。曾尝试引入，但在「单个表单标签 vs 候选字段」这种超短文本场景下，
> 词频统计缺乏语料支撑，效果不如人工词图 + 编辑距离的组合，故未保留。

### 3. ⚡ 时间切片非阻塞填充调度

- 采用 `requestIdleCallback` 时间切片，每批并发填充 6 个字段，批次之间主动让出主线程；
- 使页面在填充过程中仍能响应用户滚动与输入，不会出现整页卡顿；
- 填充操作按「读元素状态 → 写 value → 派发事件」原子执行，不做读写分离。

> 说明：本项目**未做帧率测量**，不声称具体 FPS 数字。上述设计目标是避免长任务阻塞，
> 实测瓶颈在语义匹配而非 DOM 调度（见下方实测数据）。

### 4. 📄 默认本地的 PDF / Word / JSON Resume 结构化解析

- **PDF**：离线嵌入 `pdfjs-dist` 本地 Web Worker，不依赖任何外部 CDN，彻底杜绝网络请求与 CSP 违规；
- **Word (.docx)**：结构化 Markdown 转换引擎，保留标题层级与项目列表；
- **JSON Resume**：兼容标准 JSON Resume Schema 与 OpenJobFill 自身导出格式，自动转换教育、工作、项目、技能、语言、证书和奖项；
- 自动提取姓名、电话、邮箱、多段教育/实习/项目经历，并按开始时间倒序排列；工龄只采用明确声明，不依据零散时间段推测。
- 未声明的工作年限、国家地区、学历和全日制状态保持未知；明确的 `0` 和 `false` 仍然有效。基本信息中可编辑/清空工龄与国家，教育背景可选择“未填写 / 全日制 / 非全日制”。旧档案中已有的值不会被擅自清空，请自行核对。
- “网申常用信息 → 专业技能”支持增删技能及修改熟练度，保存后用于剪贴板、字段映射和关键词分析。

### 5. 💡 问答主动学习记忆器 (Smart QA Auto-Learner)

- 在招聘网页输入开放性大题时，自动嗅探新问答并在失焦时弹出轻量保存条，一键沉淀至个人问答库，实现"越用越聪明"。

### 6. 🧪 可视化元素吸管选择器 (Visual Element Picker)

- 鼠标悬浮高亮页面任意控件，点击自动推导最优且最具唯一性的 CSS 选择器，快速定制特定站点的特殊填表规则。

### 7. 🖍️ 网页实时 JD 关键词荧光笔 (In-Page Highlighter)

- 在招聘网页原文中以高亮荧光笔标注命中技能（绿）与缺失技能（橙），缺失技能支持一键复制，助力精准修改简历。
- 岗位面板显示真实的**关键词覆盖率**：命中数 / 本次识别关键词数；零命中为 0，无可用关键词时显示“无法评估”。它是本地词典辅助核对，不使用 AI，不代表综合适合程度、ATS 初筛概率或录用概率。

### 8. 📊 求职投递看板 (Job Application Tracker)

- 8 阶段面试进度流转（已投递 ➔ 简历初筛 ➔ 笔试测评 ➔ 一面 ➔ 二面 ➔ HR 终面 ➔ Offer ➔ 流程结束）；
- 归档当前岗位时自动从页面语义节点提取公司、职位、薪资、城市和 JD 摘要；
- 优先读取标准 `JobPosting` JSON-LD，并记录字段来源；申请成功草稿可在刷新后恢复，最终仍需用户确认；
- 草稿按完整页面地址（包括岗位查询参数和 SPA hash）隔离；归档保持同一岗位来源，并保留草稿生成时的简历版本名称，不混入其他页面的 JD 或把个人期望薪资当成岗位薪资。
- 本地记录使用版本化 Schema、UUID 幂等键、字段来源与用户锁定，首次打开保持空看板，不注入演示记录；
- 支持面试笔记备忘与一键导出 **CSV 报表**（可直接用 Excel 打开）。

### 9. 🤖 可选 AI 智能兜底（本地优先）

- **默认关闭**，纯本地规则引擎即可完整使用，开箱即用无需任何配置；
- 开启后，规则识别失败的字段会交给 LLM **一次性批量映射**（省成本，而非每字段一次调用）；
- **本地优先**：推荐 Ollama 本地模型（零成本、数据不出机），也支持自带 Key 的 OpenAI 兼容云端接口；
- **隐私护栏**：日常填表兜底只发送字段「标签」，LLM 只返回映射，简历值在本地取出填充；
- **AI 简历补强**：PDF 可组合本地提取文本与最多前 4 页页面图，Word 可使用本地提取的 Markdown/文本进行结构补强；也可单独识别 JPG / PNG / WebP，均需逐次确认且结果先预览再导入；
- AI 返回的映射会再过一遍**身份排斥检查** —— 即便模型把"紧急联系人"错配到本人信息也会被拦下；
- AI 匹配的字段在填充日志中标注「AI 匹配」，便于你重点核对。在「设置 → AI 智能兜底」中配置。
- 填前预览标出“AI 建议”，说明本次请求候选数、有效新增映射数或失败后的手动补漏路径；本地结果始终保留。每次最多请求前 25 个候选。
- 文档增强展示相对本地预览新增/变化的可填字段及核对清单，支持“仅使用本地解析结果”。这些计数不是准确率；图片识别没有本地文本对照，仍需逐项核对。
- 停止导入会丢弃迟到结果，不代表已经发送的模型请求在服务方停止或不计费。云端文本/图片只在逐次授权后发送；API Key 本地保存，并在调用所选接口时用于鉴权。

### 本地备份与误操作恢复

- 投递网址可留空，正常保存的记录可随全量备份恢复；非法结构仍在写入前拒绝。
- 选择备份后先预览时间、模式和简历/规则/域名/投递数量，确认后才执行恢复；旧版简历数组只影响简历。
- 覆盖前自动保存最近一次本地恢复点；保存失败则不开始覆盖。可在偏好设置中确认“恢复覆盖前的数据”，并恢复此前激活的简历。
- 恢复点只保留最近一次覆盖前的状态，含个人敏感信息，不代替离线文件备份。全量备份不含 AI 配置与 Key、填写历史和浏览器设置，迁移后需重新配置。

### 10. ✋ 点选手动填充（漏填补救）

- 自动填充漏填或填错时，点悬浮球的「手动」进入点选模式；
- 点击网页上的输入框，从简历字段浮层中选一个填入，支持搜索、可连续点选多个；
- 成功填入后记住这次“目标控件 → 简历字段”选择，下一次在同站点可直接自动匹配；
- 全程本地，按 Esc 退出。这是 human-in-the-loop 的手动安全网。
- **剪贴板点填保持网页焦点**：先点网页输入框，再进入剪贴板搜索或点击字段，仍填入原输入框；不会误写扩展搜索框。目标被移除、禁用、改成只读或敏感控件时只复制、不写入；聚焦其他网页控件会取消旧目标。

### 11. 👁️ 填前预览确认（事前把关）

- 「一键填写」改为**先扫描生成填表规划并展示预览**：每个字段将填入什么值，一目了然；
- 核对无误后点「确认填写 N 项」才真正写入页面，不满意可取消；
- 重复经历所需的编辑、保存和新增动作也会在预览中单列；确认后按状态机逐条执行并验证，绝不点击提交或下一步；
- 需要手动补充的字段会单独标出，不会被静默跳过；
- 这把"防误填"从事后日志变成了**事前把关**，与 OfferLink / 牛客网申助手"确认后再提交"的交互一致。

### 12. 📎 简历附件注入与脱敏回放快照

- 悬浮面板可由用户主动选择本地 PDF / Word 文件，并优先注入带“简历 / Resume / CV”语义的上传区，避开头像和证件照控件；
- 每次规划与执行会生成紧凑诊断快照，递归清洗手机号、邮箱、身份证、银行卡和密钥，且不记录待填写的简历值。
- 诊断包同时记录表单根评分、平台增强器匹配轨迹、规则证据命中方式、动态经历数量和分阶段耗时；开发排障可运行不可执行的 association dry run，全程不扩展区块、不请求 AI、不写入字段值。
- 复杂控件运行时登记 58 个站点/组件 Adapter，按专项、组件库、通用与 Native 顺序执行；Phoenix、My97 等通过一次性授权的受限 MAIN-world 桥接，详见 [`docs/complex-control-adapter-matrix.md`](docs/complex-control-adapter-matrix.md)。
- 27 个版本化站点画像负责 hostname/path、共享 SaaS 模板和重复卡片工作流；兼容等级与验证门禁见 [`docs/site-profile-compatibility-lab.md`](docs/site-profile-compatibility-lab.md)。

### 13. Schema 字段元数据中心

- [`resumeFieldRegistry.ts`](src/core/schema/resumeFieldRegistry.ts) 统一管理字段路径、中文名、同义词、分组、ONE/MANY 基数、值类型、敏感等级、可填写/剪贴板/诊断导出策略；支持 `educations.0.schoolName` 与 `educations[0].schoolName` 归一化。
- 剪贴板字段、AI 映射候选、人工绑定候选和诊断脱敏共用此中心。AI 只获得实际有值字段的名称与路径，不获得值；`0`、`false` 保留为有效回答；域名专属问答仍由专门的作用域匹配器处理。
- “待办 → 记住映射”按当前简历的实际记录展开第二、第三段等经历，不再只列第一段。人工绑定允许选择尚待补全的空字段，但不会凭空创建经历；执行时仍遵守无值跳过和防误填检查，问答库不进入通用人工绑定候选。
- 注册表中的简历内容默认不进入诊断包，包括姓名、经历文本等非正则可识别的个人内容；原有联系方式、证件号和密钥清洗继续生效。

### 14. 版本化行政区划与本科专业目录

- 地区覆盖 **34 个省级分组、397 个中间层级节点、3417 个区县/乡镇节点**；完整替代原来的热门城市小表，支持代码反查、省市区路径、直辖县级单位和港澳台地址补充。同名区县缺少上下文时不擅自选第一个。
- 地区底表为 `china-division@2.7.0` 的 **2023-06-30 统计区划快照**，包含开发区；港澳台及离岛补充使用名称，缺失代码保持空值。这是本地表单匹配数据，**不是 2026 年实时法定行政区划库**。
- 本科专业使用教育部 **2026 年目录：13 个学科门类、92 个专业类、883 种专业**，保留六/七位代码与 T/K 标记；交叉学科按该版本原有层级处理，未虚构专业类。可反查软件工程、具身智能、语言智能等专业路径。
- 两套数据随扩展打包，运行时不联网。来源、许可、更新方式及本科/研究生/职业教育范围边界见 [`数据说明`](src/core/data/NOTICE.md) 与 [`维护指南`](docs/schema-data-replay.md)。

### 15. 确定性运行回放（录制 I/O 模式）

- **历史面板 → 导出问题包 / 导入问题包 / 播放按钮**：离线回放最近运行，不请求 AI、不写入真实网页、不读取真实简历值。
- v3 快照按 runId 和连续事件序号记录：AI 请求字段/允许的响应映射、执行计划、安全闸门、Adapter 路由与尝试、读回是否等价、重复区块状态迁移、上下文失效及执行统计。
- 回放复用生产执行器和重复区块状态机，以录制的 I/O 结果替代网页、计时器和控件，检查重试顺序、状态迁移、验证计数和最终结果；AI 提供严格匹配请求契约的离线响应 stub。
- 旧 v1/v2 包仍可导入和进行原有规划回放，但不会被标记为完整运行回放。预览包、取消/缺失事件、序号变化、结果差异或容量截断会明确报告。
- 最多保存最近 10 次运行，每次最多 6000 条事件；导入限制 8 MiB，重新脱敏。此模式验证**执行控制流**，不代替真实站点的 DOM 渲染、模型质量或跨域 iframe 联调。

## 🧩 业务流程与组件边界

- `FloatBall.vue` 负责悬浮入口和面板组装；填写分析、预览、执行、取消及增量规划由 `useFillSession` 统一持有状态，面板只读取状态并发出操作事件。换简历、页面变化或界面卸载会使旧会话结果失效。
- 投递草稿与归档由 `useApplicationArchive` 管理，平台资料合并由独立导入函数负责，不与填写会话共享可写状态。
- `ResumeImportModal.vue` 负责文件选择和授权交互；`resumeImportService` 负责本地/AI 解析与降级，`useResumeImport` 负责进度与结果生命周期，`ResumeImportPreview` 负责结果和完整性提示。关闭或重新选择后，迟到的结果不会覆盖新预览。
- 维护原则和行为边界见 [`业务流程模块说明`](docs/workflow-boundaries.md)。

## 🛡️ 防误填设计（本项目的重点）

自动填表这类工具，**不填错远比填得快重要**。以下机制是本项目投入最多的部分：

- **填前预览确认**：「一键填写」先扫描生成规划并展示，每个字段将填什么值都列出来，你核对后确认才写入。这是所有防错机制的最后一道、也是最直接的一道 —— 写入前你亲眼看过。
- **预览失效保护**：执行前会核对页面地址、字段节点是否仍在当前 DOM，以及简历快照版本；页面步骤、表单或简历发生变化时自动要求重新识别，避免旧计划误填。
- **`hasUsableValue` 统一门禁**：简历字段为空时绝不生成填充动作；注意 `0` 与 `false` 属于有效业务值，不会被误判为空。
- **三态布尔解析**：复选框遇到"不确定"等模糊词时拒绝盲猜，直接放弃填充。
- **身份排斥过滤**：`username` / `nickname` / `emergencyContactName` / 紧急联系人 / 推荐人 / 家属姓名等控件，
  一律不填入本人信息。多段经历回填时按置信度分级查找（站点专属 → 中文语义 → 字段名 → 宽泛兜底）。
- **容器缺失即中止**：多段经历的第 N 个区块找不到时立即中止该段，
  **绝不降级为全文档查询** —— 否则第 N 段会静默覆盖第 1 段内容。
- **统计口径一致**：`成功 + 跳过 + 失败 = 声明字段总数`。
  「跳过」= 简历里本就没值（不是故障）；「失败」= 页面找不到控件或写入失败（必须暴露给用户）。

| :--- | :--- |

| 类型检查 | `vue-tsc --noEmit` **0 错误** |

“100+ / 500+ 真实网申准确率”。真实站点脱敏样本、负样本和独立留出集应分开维护。

关于性能瓶颈的判断：语义匹配（8.17 ms）比关键词扫描（0.26 ms）高一个数量级，
优化应优先投向语义匹配，而非继续优化关键词扫描。

## 🚀 安装与运行指南

### 1. 环境准备与依赖安装
确保已安装 [Node.js](https://nodejs.org/) **24 或以上版本**和 [pnpm](https://pnpm.io/)；CI 使用 Node 24。现有 PDF 解析依赖不兼容 Node 18/20。安装依赖时会自动执行 `wxt prepare` 生成类型：
```bash
pnpm install
```

### 2. 编译打包
```bash
pnpm build
```
打包完成后，产物位于根目录下的 `.output/chrome-mv3` 文件夹。

### 3. 加载到浏览器
1. 打开 Chrome 或 Edge 浏览器，访问扩展管理页面：
   - Chrome: `chrome://extensions/`
   - Edge: `edge://extensions/`
2. 打开右上角的 **"开发者模式" (Developer mode)**；
3. 点击 **"加载已解压的扩展程序" (Load unpacked)**；
4. 选择项目中的 `.output/chrome-mv3` 目录完成加载。

### 4. 质量校验
```bash
pnpm compile          # TypeScript 类型检查
pnpm test             # 单元测试与算法回归
pnpm test:benchmark   # 算法性能基准
pnpm build && pnpm test:e2e # 真实 Chromium 扩展 smoke：字号、窄视口提示、持久化与预览填充
pnpm test:coverage    # 覆盖率报告
```
